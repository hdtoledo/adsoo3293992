Protocolo Técnico SENA

Guía Oficial de Subida de Evidencias con Git

Como aprendices en formación de Análisis y Desarrollo de Software, operamos bajo los estándares de la industria del software. Cada aprendiz cuenta con permisos de colaborador directo en el repositorio. Para mantener el proyecto estable, no utilizaremos Pull Requests por ahora, sino commits y push directos respetando estrictamente el aislamiento de carpetas.

1. Aislamiento Estricto

Trabaja únicamente dentro de tu carpeta: aprendices/tu-nombre-slug/. Nunca toques carpetas de otros compañeros.

2. Actualizar Antes de Trabajar

Ejecuta siempre git pull origin master antes de empezar tu jornada para descargar los cambios del equipo.

3. Staging Específico

Evita el git add . indiscriminado. Prepara solo tu carpeta: git add aprendices/tu-carpeta/.

4. Commits Descriptivos

Usa mensajes claros: git commit -m "feat(evidencia): sesion-01 modelo relacional".

i Flujo Paso a Paso para Subir tu Evidencia del Día

1

Sincronizar el repositorio local

Abre la terminal en la raíz del proyecto en Visual Studio Code y descarga los últimos commits subidos por tus compañeros:

git pull origin master
2

Crear los archivos de la evidencia y actualizar tu bitácora

Dentro de tu carpeta personal aprendices/tu-nombre-slug/, crea la subcarpeta de la sesión (ej. sesion-01/) y guarda allí tus archivos técnicos. Luego, abre tu index.html personal y añade una fila <tr> en la tabla con la fecha, nombre de la actividad y estado.

3

Preparar tus cambios (Staging)

Agrega únicamente tu carpeta al área de preparación de Git:

git add aprendices/tu-nombre-slug/
4

Confirmar el commit con mensaje profesional

Registra el commit indicando el número de sesión y el tema:

git commit -m "feat(evidencia): sesion-01 modelo relacional y ddl"
5

Hacer Pull y Push final a GitHub

Por seguridad, haz un pull antes del push para verificar si alguien subió un commit en ese instante, y luego publica tu evidencia:

git pull origin master
git push origin master
Centro de Diagnóstico

Solución a Errores Típicos al hacer Pull o Push

Si la terminal te muestra un mensaje en rojo, no entres en pánico. Ubica aquí el error exacto y aplica la solución:

⚠️ Error 1: [rejected - non-fast-forward] Updates were rejected because the remote contains work...

¿Por qué ocurre? Otro compañero subió un commit a GitHub antes que tú y tu copia local está desactualizada.

Solución inmediata:

git pull origin master
git push origin master

Como cada aprendiz trabaja en su propia carpeta, Git integrará los cambios de forma transparente y te permitirá hacer push inmediatamente.

⚠️ Error 2: error: Your local changes to the following files would be overwritten by merge

¿Por qué ocurre? Ejecutaste git pull teniendo archivos modificados en tu máquina sin guardar en un commit.

Solución inmediata:

git add aprendices/tu-nombre-slug/
git commit -m "feat(evidencia): guardar avance antes de sincronizar"
git pull origin master
git push origin master
⚠️ Error 3: CONFLICT (content): Merge conflict in <archivo>

¿Por qué ocurre? Ocurre si dos personas modificaron las mismas líneas del mismo archivo (por ejemplo, si alguien editó accidentalmente un archivo fuera de su carpeta).

Solución paso a paso:

  1. Abre el archivo señalado con conflicto en Visual Studio Code.
  2. Verás resaltadas las opciones: Accept Current Change, Accept Incoming Change o Accept Both Changes.
  3. Elige la opción correcta (generalmente Accept Both Changes para conservar ambos aportes).
  4. Guarda el archivo (Ctrl + S) y ejecuta en la terminal:
git add .
git commit -m "fix(merge): resolver conflicto de integracion"
git push origin master
⚠️ Error 4: fatal: Authentication failed for 'https://github.com/...'

¿Por qué ocurre? GitHub ya no admite contraseñas de cuenta por terminal; requiere un Personal Access Token (PAT) o inicio de sesión mediante el navegador (Git Credential Manager).

Solución:

En GitHub ve a: Settings > Developer settings > Personal access tokens > Tokens (classic), genera un token con permiso repo, cópialo y pégalo como contraseña cuando Git te la solicite en la terminal.

Ciberseguridad & Convivencia Técnica

Configuración de Llaves SSH en Equipos Compartidos

En los centros de formación del SENA, los computadores de las salas de desarrollo son compartidos diariamente por aprendices de diferentes fichas y jornadas (mañana, tarde y noche). Si intentas conectarte por HTTPS, Windows almacena las credenciales globales en el sistema, ocasionando que tus commits se registren a nombre de otro aprendiz o sean rechazados por permisos. Configurar tu propia Llave SSH Ed25519 en tu cuenta personal de GitHub resuelve este problema de raíz y te identifica como el autor legítimo de cada evidencia.

Regla esencial para salas compartidas:

Nunca uses la bandera --global para configurar tu nombre o correo en equipos de las salas de cómputo, ya que alterarías la configuración de los aprendices de las otras jornadas. Usa siempre configuración local en la carpeta del proyecto.

1-6 Paso a Paso: De Cero a Conexión SSH Verificada

1

Configurar tu identidad Git local (Solo en este proyecto)

Abre la terminal en la raíz de tu proyecto en Visual Studio Code y asigna tu nombre y correo institucional:

git config user.name "TU NOMBRE COMPLETO"
git config user.email "tu-correo@correo.com"
2

Generar una nueva llave SSH con algoritmo Ed25519

Ejecuta el generador de claves criptográficas con tu correo registrado en GitHub:

ssh-keygen -t ed25519 -C "tu-correo@correo.com"
  • Cuando pregunte "Enter file in which to save the key", presiona Enter para aceptar la ruta predeterminada.
  • Cuando pregunte "Enter passphrase", es altamente recomendable ingresar una contraseña personal para que nadie en la sala pueda usar tu llave sin tu autorización.
3

Copiar tu llave pública al portapapeles

Copia el contenido del archivo público (.pub). Nunca compartas el archivo privado sin extensión.

# En PowerShell:
Get-Content ~/.ssh/id_ed25519.pub | Set-Clipboard
# En Git Bash:
clip < ~/.ssh/id_ed25519.pub
# O para verla en pantalla y seleccionarla:
cat ~/.ssh/id_ed25519.pub
4

Agregar la llave SSH en tu cuenta de GitHub

  1. Ingresa a tu cuenta en github.com.
  2. Haz clic en tu foto de perfil (arriba a la derecha) y entra a Settings.
  3. En el menú de la izquierda, haz clic en SSH and GPG keys.
  4. Haz clic en el botón verde New SSH key.
  5. En Title, coloca un nombre reconocible (ej: SENA-SalaComputo-PC05).
  6. En Key type, deja seleccionada la opción Authentication Key.
  7. En el campo Key, pega el texto que copiaste en el Paso 3 (debe iniciar con ssh-ed25519 AAAA...).
  8. Haz clic en Add SSH key y confirma con tu contraseña o aplicación de GitHub si te lo solicita.
5

Comprobar la conexión segura con GitHub

Valida en tu terminal que GitHub reconoce tu llave SSH:

ssh -T git@github.com

Si te muestra el mensaje "The authenticity of host 'github.com' can't be established. Are you sure you want to continue connecting (yes/no)?", escribe yes y presiona Enter.

Respuesta de éxito esperada:
Hi tu-usuario! You've successfully authenticated, but GitHub does not provide shell access.
6

Verificar que el repositorio use la dirección SSH oficial

Revisa cómo está configurado tu remote origin y cámbialo a la URL SSH del repositorio:

# 1. Comprobar la dirección remota actual:
git remote -v
# 2. Si empieza por https://, cámbiala a la URL SSH oficial:
git remote set-url origin git@github.com:hdtoledo/adsoo3293992.git

¡Listo! A partir de este momento podrás hacer git pull y git push de forma transparente, segura y sin conflictos con otros aprendices de la sala.

Buenas Prácticas de Cierre de Sesión en el SENA

Descargar llaves de la memoria al salir:

Si no le pusiste contraseña a tu llave SSH y quieres que nadie la use después de ti, descarga las llaves de la memoria de sesión ejecutando:

ssh-add -D
Si te sale "Permission denied (publickey)":

Verifica que el agente SSH esté activo y que tu llave esté añadida:

ssh-add ~/.ssh/id_ed25519
